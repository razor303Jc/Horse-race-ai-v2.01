# 🚀 Integrated Racing Data Pipeline - Complete Guide

## Overview

The racing data pipeline has been fully integrated to provide seamless automation from file watching to database upload. When the file watcher detects new ZIP files, it automatically triggers the complete processing pipeline in the correct order.

## 📋 Pipeline Components

### 1. File Watcher (`file_watcher_enhanced.py`)

- **Purpose**: Monitors `data/daily_downloads/manual_download/` for new ZIP files
- **Features**: Automatic extraction, data validation, pipeline triggering
- **Integration**: Calls CSV mapper and database uploader automatically

### 2. CSV Mapper (`advanced_csv_mapper.py`)

- **Purpose**: Maps CSV columns to database schema using configuration
- **Features**: Handles 6 data types (races, horses, records, jockeys_stats, trainers_stats, racecard_details)
- **Output**: Creates `mapped_upload_manifest.json` for database upload

### 3. Database Uploader (`database_uploader.py`)

- **Purpose**: Uploads processed data to PostgreSQL database
- **Features**: Docker-based execution, comprehensive error handling
- **Integration**: Uses manifest from CSV mapper

### 4. Pipeline Automation (`pipeline_automation.py`)

- **Purpose**: Coordinates all components with CLI interface
- **Features**: Manual pipeline execution, status monitoring

## 🔄 Automated Pipeline Flow

```
ZIP File Drop → File Watcher → CSV Mapping → Database Upload → ML Updates
     ↓              ↓              ↓              ↓             ↓
Manual Download  Extraction    Column Map    PostgreSQL    Model Refresh
   Directory    Validation    Generation     Upload       (Future)
```

## ⚙️ Pipeline Steps in Detail

### Step 1: File Detection

- File watcher monitors `manual_download/` directory
- Detects new ZIP files automatically
- Validates file naming patterns

### Step 2: File Extraction

- Extracts ZIP files to appropriate directories
- Race cards → `cards_data/`
- Results → `results_data/`
- Validates extracted CSV structure

### Step 3: CSV Processing

```bash
# Executed automatically by file watcher:
python tools/data_processing/advanced_csv_mapper.py
```

- Loads column mapping configuration
- Processes all CSV files in data directories
- Maps columns to database schema
- Generates upload manifest with row counts

### Step 4: Database Upload

```bash
# Executed automatically via Docker:
docker run --rm \
  --network horse-racing-ai_default \
  -v /path/to/project:/app \
  -e DB_HOST=horse_racing_postgres_clean \
  horse-racing-ai_data-pipeline \
  python /app/tools/data_processing/database_uploader.py
```

- Uploads processed data to PostgreSQL
- Handles 6 tables: races, horses, records, jockeys_stats, trainers_stats, racecard_details
- Implements deduplication and validation

### Step 5: Cleanup & Archiving

- Moves processed ZIP files to archive
- Cleans up temporary directories
- Updates processing status

## 🚨 Troubleshooting

### Common Issues

1. **File Watcher Not Starting**

   ```bash
   # Check if directories exist
   ls -la data/daily_downloads/

   # Create if missing
   mkdir -p data/daily_downloads/manual_download
   ```

2. **CSV Mapping Fails**

   ```bash
   # Check configuration
   cat config/csv_column_mapping.json

   # Verify CSV files exist
   find data/daily_downloads/ -name "*.csv"
   ```

3. **Database Upload Fails**

   ```bash
   # Check Docker containers
   docker ps | grep postgres

   # Check network
   docker network ls | grep horse-racing-ai
   ```

4. **Pipeline Stuck**

   ```bash
   # Check processing status
   cat data/daily_downloads/processing_status.json

   # Reset status if needed
   rm data/daily_downloads/processing_status.json
   ```

### Log Analysis

```bash
# Search for errors in logs
grep -i error logs/*.log

# Check recent pipeline activity
grep -i "pipeline" logs/file_watcher.log | tail -20
```
